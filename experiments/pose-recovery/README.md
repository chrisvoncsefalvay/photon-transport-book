# Primary pose recovery

This driver composes the actual CUDA projector, transmission, objective, pose VJP and safeguarded L-BFGS solver. The positive quadratic attenuation field is an analytic software fixture. The target is the expected image at a known pose, generated by the same discrete operator; it is neither a sampled exposure nor an independent physical measurement.

From the repository root:

```bash
PYTHONPATH=python uv run --group gpu python experiments/pose-recovery/run.py --output /absolute/private/new-pose-run
```

The 9 September 2026 GB10 acceptance and integration runs completed all three prescribed starts and met their configured geometric criteria. These same-discretisation results establish software consistency. The configuration remains the protocol; actual values and termination reasons belong to each run record. The run records each termination reason, accepted loss, scaled coordinates, rigid transform, held-out object-landmark error and perspective reprojection error. A smaller loss does not set the geometric success flag by itself. Symmetry, weak single-view directions, discretisation and limited capture range can all cause declared failures.

The fixed chart orders translation then rotation, with scales `(1 mm, 1 mm, 1 mm, 0.01 rad, 0.01 rad, 0.01 rad)`. Each initial condition starts a fresh optimisation history. Images and adjoints stay on CUDA; the controller transfers only the rigid transform, six derivatives, objective and diagnostic status. Source/configuration snapshots and actual device metadata accompany the raw JSON records. The output directory must be new and outside the repository. This driver creates no plots or book artefacts.

Acceptance requires the operator and composed directional checks first, then these prescribed starts, broader initialisation/geometry cases, independent model-mismatch experiments and real allocation/timeline profiling. Failure must remain visible; changing tolerances after seeing a result requires a new declared run.
